# Publication checklist

A tool or repository is not ready to become public until every applicable item
is complete.

## Ownership and legal

- [ ] A Certiv maintainer owns releases and issue response.
- [ ] Certiv has approved the repository and tool names.
- [x] Apache-2.0 replaces the source-visible preview notice.
- [ ] Intellectual-property and third-party-code review is complete.
- [ ] Git history and current files pass a secret scan.

## Product and security

- [ ] The advertised happy path works without a Certiv account.
- [ ] Network access, telemetry, and data handling are documented.
- [ ] Threat and abuse review is complete.
- [ ] Third-party service terms and branding review is complete for integrations.
- [ ] Dependencies and release artifacts are scanned.
- [ ] `SECURITY.md` contains a working private reporting route.

## Documentation and usability

- [ ] A new user can complete the quick start in under ten minutes.
- [ ] All README commands have been run from a clean checkout.
- [ ] Limitations, suppressions, exit codes, and supported versions are stated.
- [ ] Internal identifiers and Certiv-only assumptions are removed.
- [ ] Staged/internal notices are replaced with the final public status.
- [ ] Relative and external README links resolve.

## Distribution

- [ ] The repository description, topics, homepage, and social preview are set.
- [ ] The dedicated `certiv.ai/tools/<slug>/` page is live.
- [ ] The website page and GitHub README link to one another.
- [ ] Markdown, JSON, `llms.txt`, and AI-catalog entries are live.
- [ ] The release has a version tag, changelog, and reproducible artifacts.
- [ ] Launch links use the agreed UTM convention.

## Measurement

- [ ] A pre-launch Search Console and analytics baseline is recorded.
- [ ] Outbound clicks from the tool page are measured.
- [ ] A 7-day and 30-day review owner and date are recorded.
